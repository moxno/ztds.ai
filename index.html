The 4 Invariants of ZTDS

Every compliant implementation must cryptographically and empirically adhere to these rules.

INVARIANT 01

Volatile Memory Boundary

The session token map resides strictly in volatile host RAM. Under no circumstances may mapping pairs be persisted to localStorage, cookies, IndexedDB, or swap space.

INVARIANT 02

Sub-2ms Latency Ceiling

Total parsing, entity extraction, and token substitution must complete within 2 milliseconds per 15,000-character block, ensuring zero perceptual friction for developers and users.

INVARIANT 03

Zero Network Transmission

The sanitization engine must pass the Airplane Mode Standard: complete de-identification and reverse re-identification functional with all network adapters disabled.

INVARIANT 04

Cryptographic Transport Handoff

When teams require collaborative unmasking, token maps must be encrypted using Argon2id key derivation and XChaCha20-Poly1305 symmetric authenticated encryption.
