Architecture in Plain Language

How Zero-Trust Data Sanitization Works

You don't need a complex proxy or remote server. Everything happens right inside your user's browser or on your backend server before data ever touches an external AI.

1

User Enters Private Data

Your customer pastes text, medical records, or customer support logs containing real names, emails, and account numbers.

"Customer David Cohen from Acme Corp transferred $5,000 via IBAN IL62..."
2

Local ZTDS Shield

0 Bytes Egress

The lightweight SDK replaces sensitive PII with safe tokens in volatile device memory. No data is sent to our servers or third parties.

"Customer [NAME_1] from [COMPANY_1] transferred $5,000 via IBAN [IBAN_1]"
3

Safe AI & Local Restore

OpenAI or Claude analyzes the sanitized prompt safely. When the response arrives, the SDK restores the real names locally on screen.

"Action approved: David Cohen (Acme Corp) transfer recorded. Zero raw PII was exposed."

app.ts — ZTDS Reference Pipeline
Reference: @privacyscrubber/sdk
// 1. Install reference package: npm i @privacyscrubber/sdk import { ZTDSClient } from '@privacyscrubber/sdk'; // 2. Initialize in-memory zero-trust enclave const ztds = new ZTDSClient(); // 3. Sanitize prompt locally before sending to cloud AI const { safePrompt, tokenMap } = ztds.sanitize(userPrompt); // 4. Send safe prompt to OpenAI or Anthropic (0 bytes PII leak) const aiResponse = await openai.chat.completions.create({ model: 'gpt-4o', messages: [{ role: 'user', content: safePrompt }] }); // 5. Restore original tokens locally in volatile RAM const cleanResult = ztds.restore(aiResponse.content, tokenMap);

LEGAL & COMPLIANCE MEMO

Why ZTDS-Compliant Architectures Do Not Require a DPA

Under GDPR Article 28 and EDPB doctrine, data processing agreements are legally required only when personal data is processed by a third party. Because ZTDS executes 100% in client RAM with 0 bytes transmitted to vendor servers, the vendor never qualifies as a "data processor".
