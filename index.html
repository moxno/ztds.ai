Technical & Legal Reference

Frequently Asked Questions

How does ZTDS protect sensitive data in Model Context Protocol (MCP) for Cursor and Claude Desktop? ↓

The open reference MCP server (ztds-mcp) and certified @privacyscrubber/mcp-server execute locally on the developer workstation over stdio JSON-RPC pipes. Prompts, code diffs, and tool arguments are sanitized in volatile host RAM before network transmission. Cleartext secrets, internal IPs, and customer PII are replaced with deterministic surrogate tokens ([KEY_1], [EMAIL_1]) so LLM reasoning stays intact while 0.00 bytes of raw sensitive data cross the network.

How does ZTDS solve GDPR Article 17 Right to be Forgotten in RAG vector databases? ↓

When raw PII is embedded directly into Pinecone, Qdrant, or PGVector, honoring a GDPR Article 17 erasure request requires costly re-indexing. ZTDS tokenizes direct identifiers in host RAM prior to embedding generation. Vector indices store mathematical representations of de-identified surrogate tokens rather than raw personal identifiers, and purging the local token map severs re-identification without rebuilding the vector index.

How does ZTDS eliminate intermediary sanitization subprocessors under GDPR Article 28? ↓

Cloud DLP gateways and SaaS redaction proxies ingest cleartext personal data on external servers, making them third-party processors requiring GDPR Article 28 Data Processing Agreements (DPAs). Because ZTDS executes 100% inside client volatile RAM with 0.00 bytes of cleartext egress to any sanitization vendor, no intermediary sanitization subprocessor enters the supply chain, establishing a verifiable Technical Safe Harbor under GDPR Article 32 and Israel Protection of Privacy Law Amendment 13 Section 17.

What is the difference between open reference ztds-mcp and @privacyscrubber/mcp-server? ↓

ztds-mcp is the Apache 2.0 open-source reference server maintained by the ZTDS Consortium for baseline universal PII and secret redaction. @privacyscrubber/mcp-server (and @privacyscrubber/sdk) is the Pioneer Certified Commercial Implementation engineered by BrandMeWeb, adding 30 specialized industry profiles (HIPAA Safe Harbor PHI, PCI-DSS banking/IBAN, legal privilege, cloud IAM) and offline Ed25519 token licensing for air-gapped enterprise teams.

How can I independently verify zero external network egress in my own environment? ↓

ZTDS follows the Airplane Mode Verification Protocol: load this page or install npx ztds-audit --strict, disable Wi-Fi and Ethernet interfaces, and execute tokenization and de-tokenization with 100% functionality. Inspecting Chrome DevTools Network tab or packet captures confirms 0 outbound requests and 0.00 bytes of network egress.
