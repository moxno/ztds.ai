# ZTDS Local Security Firewall — Agent Rule

## Purpose
Enforces Zero-Trust Data Sanitization (ZTDS RFC v1.0) across all agent interactions, tool calls, and LLM reasoning steps. Guarantees zero external network egress of raw PII, secrets, API tokens, and confidential corporate records.

## Operating Procedures
1. **Pre-Call Sanitization**: When analyzing files, environment configurations (.env), logs, SQL dumps, or customer records, call the `ztds_sanitize` tool before passing data into reasoning or external tools.
2. **Context Preservation**: The surrogate tokens generated by ZTDS (e.g. `[EMAIL_TOKEN_1]`, `[API_SECRET_TOKEN_1]`) preserve syntactic structure and semantic roles, enabling accurate code review and debugging without cleartext exposure.
3. **Local De-Tokenization**: If cleartext values are required for local inspection or final output, call `ztds_restore` with the active session identifier. Reversible mapping tables reside strictly in local client volatile memory.
4. **Leakage Auditing**: Use `ztds_audit` to scan source files, generate SHA-256 cryptographic compliance receipts, and detect leaked credentials.
5. **Memory Zeroization**: Call `ztds_reset_session` at the conclusion of sensitive workflows to zeroize in-memory surrogate maps immediately.
