BLUEPRINT 01 · LANGCHAIN LCEL TypeScript / Python

LangChain RunnableSequence Bijective Sanitization Middleware

Wraps any LangChain Expression Language (LCEL) chain in a stateful volatile closure. Raw user variables are sanitized in local process RAM prior to ChatOpenAI or ChatAnthropic invocation and restored locally before returning to the caller. 

import { PrivacyScrubberEngine } from "@privacyscrubber/sdk";
import { RunnableLambda } from "@langchain/core/runnables";

const engine = new PrivacyScrubberEngine({ profile: "finance" });

export async function invokeZeroTrustChain(chain, rawPrompt) {
  const { sanitizedText, tokenMap } = engine.sanitize(rawPrompt);
  try {
    const llmResponse = await chain.invoke({ input: sanitizedText });
    return engine.restore(llmResponse.content, tokenMap);
  } finally {
    engine.destroy(tokenMap); // Invariant 3 CSPRNG zeroization
  }
}
Latency Overhead: 42.8 µs (p50) Invariant 1, 2 & 3 Verified
BLUEPRINT 02 · LLAMAINDEX RAG Python / Node.js

LlamaIndex Ingestion Transform & Query Postprocessor

Intercepts retrieved document nodes and query strings in local volatile RAM before LLM synthesis. Prevents sensitive clinical or legal records stored in internal knowledge bases from crossing the external API boundary. 

from ztds import ZtdsSession

def zero_trust_rag_query(query_engine, raw_query: str, nodes: list) -> str:
    with ZtdsSession(profile="medical") as session:
        clean_query = session.sanitize(raw_query)
        for node in nodes:
            node.text = session.sanitize(node.text)
        response = query_engine.synthesize(clean_query, nodes=nodes)
        return session.restore(str(response))
    # Ephemeral tokenMap is automatically zeroized on context exit

BLUEPRINT 04 · VECTOR DB INGESTION Pinecone / Qdrant / Weaviate

Pre-Embedding Sanitization Gate for Managed Vector Stores

Raw PII embedded into high-dimensional vectors is vulnerable to embedding inversion attacks and turns your vector DB vendor into a GDPR Article 28 subprocessor. Sanitize chunks in RAM before calling embeddings.create(). 

const { sanitizedText, receipt } = engine.sanitize(rawDocumentChunk, {
  profile: "legal"
});

// 1. Generate embedding strictly over sanitized surrogate text
const vector = await openai.embeddings.create({
  model: "text-embedding-3-large",
  input: sanitizedText
});

// 2. Upsert to Pinecone with SHA-256 compliance receipt
await pineconeIndex.upsert([{
  id: chunkId,
  values: vector.data[0].embedding,
  metadata: { text: sanitizedText, ztds_sha256: receipt.sha256 }
}]);

BLUEPRINT 10 · CHROME MANIFEST V3 Browser V8 Content Script

Zero-Server Browser DOM Input Interceptor for Web AI Chats

Intercepts prompt submission events directly inside the browser tab on ChatGPT, Claude, and Gemini. Scrubs sensitive entities in local V8 memory and dispatches native InputEvent updates before the web app initiates its fetch() call. 

document.addEventListener("keydown", (event) => {
  if ((event.metaKey || event.ctrlKey) && event.key === "Enter") {
    const promptEl = document.querySelector("textarea, [contenteditable='true']");
    if (!promptEl) return;
    const { sanitizedText, tokenMap } = engine.sanitize(promptEl.value || promptEl.innerText);
    window.__ztdsActiveTokenMap = tokenMap;
    if (promptEl.value !== undefined) promptEl.value = sanitizedText;
    else promptEl.innerText = sanitizedText;
    promptEl.dispatchEvent(new Event("input", { bubbles: true }));
  }
}, true);

Architecture Q&A

Frequently Asked Questions on AI & RAG Sanitization Blueprints

How do you prevent PII leakage in LangChain and LlamaIndex RAG pipelines without breaking LLM context? ↓
By inserting an in-RAM ZTDS sanitization middleware step before prompt serialization or vector chunking, raw identifiers are replaced with deterministic typed surrogates ([NAME_1], [IBAN_1]) inside host process memory. The upstream LLM reasons over intact grammatical structures, and the local postprocessor restores original cleartext values from the ephemeral tokenMap before returning the response.
Should vector embeddings in Pinecone, Qdrant, or Weaviate be generated before or after ZTDS sanitization? ↓
To satisfy ZTDS Invariant 1 and GDPR Article 28 subprocessor exclusion, document chunks must be sanitized in local volatile memory prior to calling external embedding APIs (such as text-embedding-3-large) or indexing into managed vector databases. Embedding sanitized text prevents vector inversion attacks and eliminates PII storage inside third-party vector clusters.
How does ZTDS handle streaming Server-Sent Events (SSE) when restoring surrogate tokens in real time? ↓
When an LLM streams token chunks via Server-Sent Events (SSE), a bracket-aware sliding buffer holds characters locally only when an opening bracket ([) is detected until the closing bracket (]) arrives. Complete surrogate tokens ([EMAIL_1]) are resolved against the local volatile tokenMap in sub-millisecond time without delaying normal prose streaming.
How does the Model Context Protocol (MCP) stdio firewall protect Cursor, Claude Desktop, and IDE agents? ↓
The ZTDS MCP server executes locally over standard input/output (stdio) on the developer workstation. Before an IDE agent forwards database rows, log files, or code snippets to a cloud model, it invokes ztds_sanitize in RAM, transmits only surrogate tokens over HTTPS, and invokes ztds_restore locally when unmasked values are required.
What is the difference between the open-source @ztds/core reference baseline and the commercial @privacyscrubber/sdk engine? ↓
The open-source @ztds/core and ztds Python packages provide the Apache 2.0 reference implementation for universal consumer PII and RFC v1.0 invariant verification. Enterprise production workloads requiring 30 specialized industry profiles (HIPAA Safe Harbor, SWIFT/IBAN FinTech, FRE 502 Legal, Multimodal Burn-In) and air-gapped Ed25519 node licensing deploy @privacyscrubber/sdk.
