Frequently Asked Questions

What makes a ZTDS counterfactual post-mortem different from breach news? +/-

Each counterfactual maps verified primary advisory timelines step by step to ZTDS RFC v1.0 invariants. Every page also documents explicit control limits so architects see both prevented exposure and remaining perimeter risks.

Does ZTDS eliminate cloud subprocessor security incidents entirely? +/-

No. ZTDS removes raw PII and pasted tokens from outbound inference payloads via local RAM tokenization. Organizations still require vendor IAM controls, extension signing verification, TLS, and runtime sandboxing.

How does client-side tokenization help under GDPR Article 32 and Israel Amendment 13? +/-

Stripping direct identifiers before network transmission minimizes downstream breach blast radius and supports technical safe-harbor documentation under GDPR Article 32 and Israel Protection of Privacy Law Amendment 13 Section 17.

How can engineering teams verify incident readiness locally today? +/-

Teams can run npx ztds-audit --conformance to validate synthetic vector isolation, or install the Apache-2.0 and MIT reference libraries and test certified implementations listed in the ZTDS Verified Registry.
