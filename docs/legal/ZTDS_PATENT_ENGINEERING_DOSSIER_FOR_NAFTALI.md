# מבוא והנחיות יסוד לבוחן הפטנטים (Foundational Architecture Overview)

מסמך זה מהווה את **התשתית ההנדסית המלאה והמפורטת** לתיאור ששת הסרטוטים (Sheets 1–6) שהוגשו עבור בקשת ההמשך הישראלית (Continuation Application) ובקשת ה-PCT הבינלאומית.

כדי להתגבר על מבחני הפטנטביליות של תוכנה ואלגוריתמים (הלכת *Alice* בארה"ב, דרישות סעיף 3 לחוק הפטנטים הישראלי, ודרישות ה-EPO ל-Technical Character), המערכת אינה מוגדרת כאלגוריתם מופשט, אלא כ**מערכת מחשוב מבוזרת מבודדת חומרה (Hardware-Isolated Distributed Computing System)** המשלבת שלושה מישורי אמון פיזיים נפרדים:
1. **מישור נקודת הקצה של הלקוח (Client Endpoint Plane - 100):** פועל בתוך זיכרון נדיף מבודד (Isolated Volatile RAM / Heap Sandbox) של מעבד המשתמש (CPU 1), ללא זכות גישה לממשקי אחסון קבועים (Non-Volatile Disk).
2. **מישור אימות המדיניות (Policy & Attestation Decision Plane - 200):** שרת בקרה ייעודי המאמת ראיות חומרה קריפטוגרפיות (Hardware Root of Trust).
3. **מישור מחשוב חסוי בחומרה (Hardware Confidential Enclave Plane - 300):** מובלעת חומרה פיזית מבודדת (AWS Nitro Enclaves) המתקשרת אך ורק דרך אפיק פנימי מבודד (`AF_VSOCK`), ללא שום כרטיס רשת חיצוני (Zero External NICs).

## שרטוט 1 (FIG. 1): ארכיטקטורת המערכת הכללית ושלושת מישורי האמון (High-Level System Architecture)

שרטוט 1 מדגים מערכת מחשוב מבוזרת המבצעת סניטציה דטרמיניסטית בזיכרון נדיף ללא זליגת נתונים לרשת, ומורכבת משלושה מישורים פיזיים ולוגיים נפרדים:

### [100] מישור תחנת הקצה של הלקוח (Client Endpoint)
* **מהות פיזית וחומרתית:** התקן מחשוב של משתמש קצה (מחשב נייד, תחנת עבודה, שרת מקומי) הכולל מעבד מרכזי (Host CPU) וזיכרון נדיף (Volatile RAM). התוכנה פועלת בתוך ארגז חול של דפדפן (Browser Engine Sandbox V8), תוסף דפדפן (Manifest V3), תהליך מקומי (Local Daemon / IDE) או סביבת WebAssembly (WASM).
* **בידוד פיזי:** זיכרון התהליך נעול באמצעות פקודת מערכת הפעלה (`mlock`) המונעת דפדוף של המידע לדיסק (Anti-Swap Paging).

#### פירוט רכיבי תחנת הקצה [100]:
* **[102] מאגר קלט גולמי בלתי-מסונן (User Cleartext Input):**
  * **מהות:** חוצץ קלט פיזי בזיכרון ה-RAM (Buffer) המקבל מחרוזות טקסט בלתי מובנות ישירות ממקלדת המשתמש, קובץ מקומי, או ממשק API לפני שידורן לרשת.
  * **קלט:** טקסט חופשי הכולל מידע אישי מזהה רגיש (PII), מידע רפואי מוגן (PHI), נתוני שכר (W-2), מספרי חשבונות בנק (IBAN), מפתחות גישה לענן (API Keys).
  * **פלט:** מחרוזת תווים בלתי-מטופלת המועברת לעיבוד פנימי של מנוע ה-DFA [104].
* **[104] מנוע אוטומט סופי דטרמיניסטי (Client DFA Engine - S_RAM Runtime):**
  * **מהות:** מודול תוכנה המבצע סריקה לקסיקלית של חוצץ הקלט בזמן ריצה ליניארי $O(N)$ (כאשר $N$ הוא אורך הטקסט), ללא נסיגה לאחור (Zero Catastrophic ReDoS Backtracking).
  * **קלט:** מחרוזת הטקסט הגולמית מחוצץ [102].
  * **פלט:** מערך טופלים הכולל: סוג הישות (Entity Type), מיקום תו התחלה (Start Offset), מיקום תו סיום (End Offset), והערך הגולמי.
* **[106] מנוע החלפת טוקנים לפי היסט יורד (Token Substitution Engine):**
  * **מהות:** מודול עיבוד מניפולציית מחרוזות ב-RAM הפועל לפי חוק אינווריאנטי קריטי: מיון היסטים בסדר יורד מהסוף להתחלה (`Sort Descending by Start Offset`). שיטה זו מבטיחה כי שינוי אורך המחרוזת כתוצאה מהכנסת טוקן אינו משבש את כתובות האינדקס של הישויות הקודמות במחרוזת.
  * **קלט:** טקסט גולמי ומערך הישויות הממוין בסדר יורד.
  * **פלט:** מחרוזת טקסט מסוננת ($Q_T$) שבה כל ישות הוחלפה בטוקן סורוגטי דטרמיניסטי בתבנית סוגרית `[TYPE_N]` (למשל `[EMAIL_1]`, `[NAME_1]`).
* **[108] טבלת מיפוי סשן נדיפה (Volatile Session Map - $M_s$):**
  * **מהות:** מבנה נתונים בינארי מסוג Hash Map השוכן אך ורק בתוך הזיכרון הנדיף (RAM Heap) של התהליך. הטבלה מקשרת באופן חד-חד-ערכי (Bijective) בין הטוקן הסורוגטי לבין ערך הטקסט הגולמי המקורי.
  * **אבטחה פיזית:** המיפוי מבודד ברמת הטאב/הסשן. בעת סגירת הסשן מבוצעת פקודת איפוס פיזית בזיכרון (`explicit_bzero` / Cryptographic Zeroization) המוחקת כל שריד מידע. אין שום כתיבה למאגרי אחסון קבועים (No Disk Persistence, No Cookies).
* **[110] חוצץ שידור שאילתה מסוננת ($Q_T$ - Sanitized Query Buffer):**
  * **מהות:** חוצץ יציאה בזיכרון המכיל את הטקסט המטוהר המיועד לשידור ברשת. החוצץ מכיל 0 בתים של טקסט גולמי רגיש (0 Bytes Cleartext Egress).
* **[112] מודול שחזור מקומי (Local Rehydration Unit):**
  * **מהות:** מודול עיבוד מקומי המקבל את התשובה המעובדת ($R_T$) החוזרת ממודל ה-AI, סורק את הטוקנים הסורוגטיים שבה, ומחליף אותם חזרה בערכי המקור השמורים בטבלה [108]. התוצאה מוצגת למשתמש מבלי שמידע רגיש יצא אי-פעם מתחנת הקצה.

### [200] מישור אימות המדיניות (Policy & Attestation Decision Plane - PDP)
* **מהות פיזית וחומרתית:** שרת אבטחה או שער רשת (Security Proxy / Policy Gateway) הממוקם בין נקודת הקצה לבין מובלעת החומרה. השרת כולל מעבד ייעודי ורכיב הצפנה חומרתי (Hardware Security Module).

#### פירוט רכיבי מישור המדיניות [200]:
* **[202] יחידת אתגור קריפטוגרפי (Challenge Nonce Generator - $n_e$):**
  * **מהות:** מחולל מספרים אקראיים חומרתי (Hardware TRNG) המייצר ערך אתגר קריפטוגרפי ייחודי באורך 256 סיביות להבטחת רעננות (Freshness) ומניעת התקפות שידור חוזר (Replay Attacks).
* **[204] מנוע הערכת ראיות חומרה (Evidence Appraisal Engine):**
  * **מהות:** מעבד קריפטוגרפי הבודק את מסמך האימות החומרתי (Attestation Document) החתום דיגיטלית בתקן COSE על ידי מובלעת החומרה. המנוע מוודא את שרשרת התעודות מול שורש האמון (Root of Trust) של יצרן המעבד (AWS/Nitro CA), ומאמת את אוגרי מדידות החומרה (PCR0, PCR1, PCR2).
* **[206] שער מדיניות סשן (PDP Session Gate):**
  * **מהות:** מודול לוגיקה חסומה המנפיק כרטיס הרשאה קצר-מועד ($\tau_s$ - Ephemeral Session Token) המוצמד למדידות ה-PCR של האנקלב ולמזהה הבקשה. אם יש חריגה ב-PCR, המערכת ננעלת מיד (Fail-Closed).
* **[208] נתב שידור מורשה (Authorized Forward Proxy):**
  * **מהות:** מודול ניתוב המעביר את השאילתה המסוננת $Q_T$ לאנקלב רק לאחר הצגת כרטיס $\tau_s$ תקף.

---

### [300] מישור מובלעת החומרה המבודדת (Hardware Confidential Enclave - AWS Nitro)
* **מהות פיזית וחומרתית:** מעבד ייעודי מבודד חומרה הפועל ללא מערכת הפעלה כללית, ללא דיסק קשיח, ללא גישה למנהלי מערכת (Zero Root Access), וללא כרטיסי רשת פיזיים (No External NICs).

#### פירוט רכיבי האנקלב [300]:
* **[302] ערוץ תקשורת פנימי מבודד (`AF_VSOCK Link`):**
  * **מהות:** ממשק תקשורת וירטואלי מבודד ברמת ה-Hypervisor (Vsock Socket) המאפשר העברת מידע נקודה-לנקודה בלבד בין שרת הבקרה לאנקלב ללא ניתוב לרשת האינטרנט.
* **[304] רכיב אבטחת חומרה ייעודי (Nitro Security Module - NSM / Hardware Attester):**
  * **מהות:** רכיב חומרה פנימי של האנקלב המייצר את מסמך הראיה ($E_e$) הכולל את חתימת האנקלב על האתגר $n_e$ ומדידות ה-PCR.
* **[306] ליבת עיבוד AI פנימית (Enclave AI Core):**
  * **מהות:** מנוע ריצה פנימי המבצע היסק מודל (LLM Inference / RAG) אך ורק על גבי הטוקנים המסוננים $Q_T$, ומחזיר תשובה מעובדת $R_T$ המכילה טוקנים בלבד.

## שרטוט 2 (FIG. 2): תרשים רצף לוגי ל-7 שלבי אימות החומרה והשידור החסום (7-Phase Attestation Protocol)

שרטוט 2 מפרט את הפרוטוקול הקריפטוגרפי הדו-כיווני:
1. **שלב 1 (Step 1 - Challenge):** יחידת האתגור [202] משדרת אתגר אקראי $n_e$ לאנקלב [300].
2. **שלב 2 (Step 2 - Attestation Evidence):** מודול ה-NSM [304] של האנקלב מחזיר מסמך חתום $E_e$ המכיל גיבוב חומרתי של ה-Image (PCR0), הקרנל (PCR1) והאפליקציה (PCR2) יחד עם $n_e$.
3. **שלב 3 (Step 3 - Verification):** שרת ה-PDP [204] מאמת את החתימה ושורש האמון.
4. **שלב 4 (Step 4 - Token Issuance):** שער ה-PDP מנפיק כרטיס גישה מוגבל בזמן $\tau_s$ המוצמד למזהה האנקלב ולמזהה הבקשה.
5. **שלב 5א (Step 5a - RAM Sanitization):** תחנת הקצה [100] מבצעת סניטציה בזיכרון, מייצרת את טבלת המיפוי $M_s$, וממירה את הטקסט ל-$Q_T$.
6. **שלב 5ב (Step 5b - Dispatch via VSOCK):** שידור $Q_T$ בליווי $\tau_s$ אל האנקלב דרך שקע `AF_VSOCK` [302]. האנקלב מעבד את הטוקנים ומפיק תשובה $R_T$.
7. **שלב 6 (Step 6 - Return Response):** תשובת האנקלב $R_T$ מוחזרת כשהיא חתומה ומקושרת למזהה הסשן.
8. **שלב 7 (Step 7 - Local Rehydration):** מודול השחזור [112] בתחנת הקצה פותח את הטוקנים בתוך ה-RAM של הדפדפן ומציג את הטקסט המלא למשתמש.

## שרטוט 3 (FIG. 3): מבנה פנימי של מנוע הסניטציה ומנגנון המיון היורד (Client-Side S_RAM Engine Architecture)

שרטוט 3 מפרט את הליבה הטכנית המונעת שגיאות אינדקס בזיכרון:
* **[302] חוצץ קלט גולמי (Raw Input Stream Buffer):** אפיק כניסה לקלט הטקסטואלי.
* **[304] מערך מפענחים לקסיקליים רב-פרופילי (Multi-Profile DFA Matcher):**
  * **[304A] פרופיל כללי (General):** שמות פרטיים, מספרי תעודות זהות, מספרי טלפון, כתובות דוא"ל.
  * **[304B] פרופיל פיננסי (Finance):** מספרי חשבון בנק (IBAN), כרטיסי אשראי, שדות W-2, מספרי חשבונות ספר ראשי (GL).
  * **[304C] פרופיל רפואי (Medical - HIPAA Safe Harbor):** 18 מזהי HIPAA, מספרי תיק רפואי (MRN), תרופות מרשם.
  * **[304D] פרופיל פיתוח/אבטחה (DevOps/API):** מפתחות גישה לענן (AWS Access Keys), טוקנים מאומתים (JWT), מחרוזות חיבור לבסיסי נתונים, סיסמאות.
* **[306] חוצץ חילוץ היסטים (Entity Offset Extraction Buffer):** שומר טופל לכל ישות: `{type, start_offset, end_offset, cleartext_value}`.
* **[308] ממיין היסטים יורד (Descending Character Offset Sorter):**
  * **החידוש ההנדסי (Crucial Invariant):** מיון כל הישויות לפי `start_offset` בסדר יורד. החלפת הישות בטוקן משנה את אורך המחרוזת (למשל, החלפת שם בן 15 תווים בטוקן בן 8 תווים). ביצוע ההחלפה מהסוף להתחלה מונע משינוי האורך לקלקל את כתובות האינדקס של הישויות הקודמות.
* **[310] מקצה טוקנים בזיכרון (In-Memory Token Allocator):** מייצר תוויות סורוגטיות ייחודיות כגון `[NAME_1]`, `[EMAIL_1]`.
* **[312] טבלת מיפוי סשן נדיפה ($M_s$):** שמירת המיפוי החד-חד-ערכי ב-RAM בלבד.
* **[314] חוצץ פלט שאילתה מסוננת ($Q_T$):** שידור המחרוזת החוצה לרשת.
* **[316] יחידת שחזור הפוכה (Reverse Detokenization Unit):** החלפת טוקנים בערכי מקור בזיכרון הלקוח.

## שרטוט 4 (FIG. 4): בנצ'מרקים אמפיריים — השוואת ביצועים מול שרתי פרוקסי ענן קונבנציונליים (Performance Evaluation)

שרטוט 4 מוכיח יתרון טכני מובהק (Technical Advantage) בהפחתת זמני השהיה והגדלת קצב תעבורה:
* **FIG. 4A (השוואת זמני השהיה - Latency Scaling):**
  * בגודל מטען של **1 KiB:** המערכת משיגה השהיה ממוצעת של **0.553 מילי-שניות** לעומת **0.929 מילי-שניות** בפרוקסי מרכזי מבוסס ענן (מהיר פי 1.68×).
  * בגודל מטען של **4 KiB:** השהיה של **1.360 מילי-שניות** לעומת **1.768 מילי-שניות** (מהיר פי 1.30×).
  * המדידות מוכיחות כי סניטציה מקומית ב-RAM חוסכת Round-Trip Time (RTT) של הרשת ומבטלת צווארי בקבוק.
* **FIG. 4B (השוואת קצב תעבורה - Steady-State Throughput RPS):**
  * עבור **1 KiB:** המערכת תומכת ב-**1,808 בקשות לשנייה (RPS)** לעומת 1,057 בלבד בפרוקסי קונבנציונלי (יתרון תפוקה של פי 1.71×).
  * עבור **4 KiB:** קצב של **735 RPS** לעומת 556 RPS (פי 1.32×).

## שרטוט 5 (FIG. 5): מטריצת ולידציה על קורפוס קפוא וביקורת היעדר זליגה חומרתית (Validation Matrix & Egress Audit)

שרטוט 5 מציג נתונים אמפיריים המוכיחים אפס זליגת מידע ודיוק מושלם:
* **[500] קורפוס מבחן סינתטי קפוא (Held-Out Benchmark Corpus):** 1,925 ישויות מידע אישי על פני 3 עולמות תוכן ארגוניים:
  * **[502A] שכר ומיסוי ארגוני (W-2):** 625 ישויות; דיוק (Precision) 1.000, כיסוי (Recall) 1.000, ציון F1 של 1.000.
  * **[502B] רשומות רפואיות קליניות (EHR):** 600 ישויות; Precision 1.000, Recall 1.000, F1 1.000.
  * **[502C] רשומות פיתוח וקוד (DevOps Logs):** 700 ישויות; Precision 1.000, Recall 1.000, F1 1.000.
  * **[504] סיכום מאומת כולל:** 1,925 מתוך 1,925 ישויות זוהו במדויק ללא שגיאות False Positive או False Negative.
* **[510] מנגנוני ביקורת חומרה ורשת (Hardware & Network Audit Verification):**
  * **[512] מלכודת שקעי רשת (Socket Trap Invariant):** ניטור רמת קרנל (Libc socket trapping) המוכיח כי **0 שקעי TCP/UDP/TLS** נפתחו עם טקסט גולמי. זליגת רשת = 0 בתים.
  * **[514] בידוד זיכרון נדיף (RAM Isolation Invariant):** הוכחת היעדר שמירה על דיסק; איפוס מוחלט של זיכרון ה-Heap בסגירת סשן (0 בתים שיוריים).
  * **[516] אימות הצמדת PCR ואתגר אקראי:** PCR0 מאמת את קובץ האנקלב (EIF), PCR1 מאמת את הקרנל, ו-PCR2 מאמת את קוד האפליקציה. אי-התאמה כלשהי גורמת לחסימה מיידית (Fail-Closed) בתוך פחות מ-1 מילי-שנייה.

# נספח שמות ומונחים מדויקים לשימוש בתביעות (Claims Lexicon)

כדי להבטיח אחידות מוחלטת בין גוף הפירוט (Specification) לבין כתב התביעות (Claims) בבקשת ההמשך, יש להשתמש במונחים המדויקים הבאים:

1. **Client Computing Device / Endpoint [100]** — התקן מחשוב של לקוח.
2. **Volatile Host Memory / Isolated RAM Sandbox [100, 108, 312]** — זיכרון נדיף מארח מבודד.
3. **Deterministic Finite Automaton (DFA) Lexical Matcher [104, 304]** — מפענח לקסיקלי מבוסס אוטומט סופי דטרמיניסטי.
4. **Descending Character Offset Sorter [106, 308]** — ממיין היסטים יורד של תווי ישויות.
5. **Bidirectional Surrogate Session Mapping Table [108, 312]** — טבלת מיפוי סשן סורוגטית דו-כיוונית בזיכרון נדיף.
6. **Cryptographic Memory Zeroization Primitive [108, 514]** — פקודת איפוס קריפטוגרפי בזיכרון נדיף.
7. **Hardware-Attested Confidential Execution Enclave [300]** — מובלעת מחשוב חסוי מאומתת חומרה.
8. **Isolated Hypervisor Inter-Process Channel (`AF_VSOCK`) [302]** — ערוץ תקשורת מבודד מבוסס שקע וירטואלי של הייפרווייזור.
9. **Platform Configuration Registers (PCR) State Binding [204, 206, 516]** — הצמדת מצב אוגרי תצורת פלטפורמת חומרה.
10. **Hardware-Attested Return-Path Session Continuation (ZTDS-ARC) [112, 316]** — המשכיות אימות נתיב חזרה מאומתת חומרה וצמודת סשן.
